## 来源层级说明

判断引用可信度时必须先看层级。同一份文件在不同站点内容可能一致，但**权威性不同**：

| 层级 | 含义 | 本项目的用法 |
| --- | --- | --- |
| **A 官网原件** | 发文机关官网发布的原文或原始附件 | 规则阈值的唯一依据 |
| **B 政府转载** | 其他政府网站（公报、地方转发）转载 | 用于交叉核对条文是否有出入 |
| **C 商业法规库 / 媒体** | 法规数据库、新闻媒体转载 | **只用于定位线索**，不作为阈值依据 |

### ⚠️ 这个 xls 里有两个工作表，只有一个能用

解析后（见 `2016-71/extracted/_dump.txt`）发现文件含两个工作表：

| 工作表 | 标题 | 性质 | 能否用于取数 |
| --- | --- | --- | --- |
| **Sheet1** | 中央和国家机关工作人员赴地方差旅住宿费标准明细表 | 正式发布的明细表 | ✅ **唯一的取数依据** |
| **Sheet3** | 中央部门差旅住宿费限额标准修改建议调查表-汇总4 | **征求意见用的调查表**，含民革、民进、国管局、工商总局四家提出的建议值 | ❌ **不得用于取数** |

**为什么必须写清楚**：Sheet3 是标准制定过程中的内部工作稿，被一并留在了附件文件里。
四家单位在同一地区给出的建议值各不相同，且**与正式发布值不一致**。例如北京：

| 来源 | 部级 | 司局级 | 其他人员 |
| --- | --- | --- | --- |
| Sheet3 · 民革建议 | 900 | 600 | 400 |
| Sheet3 · 国管局建议 | 960 | 600 | 500 |
| Sheet3 · 工商总局建议 | 1000 | 650 | 500 |
| **Sheet1 · 正式发布** | **1100** | **650** | **500** |

把 Sheet3 当成标准会在规则库里引入错误阈值，而且这种错误很难被发现——
它看起来也是「表格里的数」。

**这是本项目遇到的第一个数据来源陷阱，记在 `docs/ambiguity-log.md` 里。**
处理方式：Sheet3 保留存档（它本身是有价值的过程材料），但在取数脚本里明确排除，
并在规则元数据中标注所有住宿费阈值均来自 Sheet1。

### Sheet1 的结构

| 列 | 含义 |
| --- | --- |
| 序号 / 地区 | 省级地区编号与名称（共 36 行） |
| 子区域 | 该省内的适用范围（如「南京市、苏州市…」或「其他地区」） |
| 住宿费标准 | **部级 / 司局级 / 其他人员** 三档，单位元/人·天 |
| 旺季地区 / 旺季期间 / 旺季上浮价 | 部分城市在特定月份适用更高的上浮价（同样三档） |

**结构上的两点值得注意**：

1. 同一省份可能有多行子区域。例如四川有 7 行（成都 / 阿坝甘孜 / 绵阳乐山雅安 / 宜宾 /
   凉山 / 德阳遂宁巴中 / 其他地区），青海 5 行，陕西 6 行，新疆 6 行。
2. 多数省份最后一行是「**其他地区**」——这是个**兜底行**，作用是保证省内没有遗漏区域。
   在规则库里，兜底规则正是保证「完整性」（不留缺口）的机制；
   把它删掉或改错，就会出现诊断层能抓到的缺口。

附表标注为「**略，详情请登录财政部网站**」。

但这些数值来自地方政府网站转载与高校文件（B/C 层级），**不是财政部原件**。

**处理原则**：
- 若由人工从 B/C 层级来源抄录，规则元数据里必须标注**来源层级为 B/C**，
  与住宿费规则（A 层级原件）区分开
- **不得**在文档里把这个数值说成「取自财政部官网原件」
- 待找到 A 层级来源后升级

## 七、复核方式

原始文件的完整性可以用校验值核对：

```bash
sha256sum sources/**/*.html sources/**/*.xls   # 前 16 位应与上表一致
```

条文数可以用脚本复核：

```bash
python scripts/extract_text.py sources/2013-531/raw-govcn.html /tmp/check.txt
grep -o "第[一二三四五六七八九十百]*条" /tmp/check.txt | sort -u | wc -l   # 应为 33
```
