## 1. 主流程：五道关卡的顺序是有理由的

`src/claimcheck/engine.py:103-188`　函数 `run()`

**做什么**：对一份申请跑全部规则。每条规则依次过五道关：版本门 → 范围匹配 →
`when` 匹配 → 阈值门 → 求值。

**为什么是这个顺序**：

- **版本门在最前**：2013 年的单据不该被 2016 年的阈值判。这个判断不依赖任何数据，最便宜也最硬。
- **范围匹配在阈值门之前**：一份南京的申请，不该因为「黑龙江的阈值没覆盖这个时段」而报信息不足。
  先确认这条规则*管不管这个地方*，再确认它的*数值有没有*。
- **阈值门单独存在**：条款生效了（2014），但阈值来自另一份文件（2016）。
  条款在、阈值不在 → 输出「信息不足」，不是跳过。跳过等于假装这条规则不存在。

**面试怎么用**：被问「你怎么保证判断是对的」，答「先排除不适用的，再判断适用的，
最后处理判不了的」，比罗列功能强。

## 2. 「制度未覆盖」必须独立于「通过」

`src/claimcheck/engine.py:190-217`　函数 `_uncovered_categories()`

**做什么**：找出本申请里「规则库根本没有对应规则」的费用类别，单独补一条结果。

**为什么这样写**：这是全项目最容易出错、也最能说明问题的一处。

如果一整类费用没有规则管，它就不产生任何结果；整体结论从「所有结果里取最坏」，
于是变成「通过」——**规则库的缺口被伪装成了合规**。

这里判的是「规则库里有没有」，不是「这个时段适不适用」（后者由阈值门处理，
输出信息不足）。两者含义不同：一个是知识缺失，一个是时间不匹配。

**面试怎么用**：被问「系统怎么知道自己不知道」，这是最直接的答案。
它能展开成一句原则：**规则库的输出语义不能撒谎。**

## 3. 冲突按「结论是否分歧」判定

`src/claimcheck/engine.py:219-244`　函数 `_resolve_conflicts()`

**做什么**：两条规则都命中同一份申请时，比较它们各自的结论：相同就按该结论，
不同才一起改判「需人工确认」。

**为什么不是「一命中就转人工」**：那会让两条规则互相抵消，正常情形也判不了。
典型例子：司局级住标准间，531 号允许、497 号也不限制 → 一致 → 通过；
部级住标准间，531 号要求套间、497 号放行 → 分歧 → 转人工。

**面试怎么用**：这道题能区分「真想过」和「抄了个冲突检测概念」。

---

## 4. 三值逻辑：缺字段既不能当假也不能当真

`src/claimcheck/predicate.py:28-160`　`Tri` 枚举与 `evaluate()`

**做什么**：谓词求值返回 **真 / 假 / 未知**，不是布尔值。

**为什么**：某晚的 `receipt_present` 没填——默认 false 会误报「缺发票」，
默认 true 会漏报。返回「未知」→ 上层输出「信息不足」→ 申请人补齐就能重判。

短路规则：`any` 有一个真就是真，否则有未知就是未知；`all` 有一个假就是假，
否则有未知就是未知；`not 未知 = 未知`。

**实现上有个坑**：`Tri` 显式让 `__bool__` 抛异常，防止有人写成 `if result:`
——那会把 `Tri.UNKNOWN` 当成真，静默出错。

**面试怎么用**：被问「数据不全怎么办」时最有说服力的例子。能一路讲到
「系统的输出语义不能撒谎」这条贯穿全项目的原则。

## 5. 阈值检查：逐晚判断，旺季按月份选限额

`src/claimcheck/checks.py:59-141`　函数 `check_threshold()`

**做什么**：把一晚一晚的金额与限额比较。限额按「人员级别」取；若该晚落在旺季月份，
换成旺季限额。

**为什么逐晚而不是总额÷天数**：两个硬理由。
1. 旺季规则判不了——只知道「住了 3 晚」，无法判断哪几晚落在 7–9 月。
2. 均价掩盖超标——3 晚共 1200，均价 400 看着合规，但可能是 500/500/200。

**面试怎么用**：「你怎么防止漏检」这个问题，这条能答得很具体。

---

## 6. 检查项展开：规则是编写单位，检查项是统计单位

`src/claimcheck/checks.py:367-407`　函数 `expand_check_items()`

**做什么**：静态展开一条规则包含哪些可独立统计的判断。江苏一条规则（三个级别）→ 3 个检查项；
交通等级一条规则（3 级别 × 4 交通工具）→ 12 个检查项。

**为什么分两层**：如果按「规则命中率」统计覆盖，会出现「规则 100% 命中、
但某个级别的阈值从没被测试过」的假信号。这正是要避免的那类指标失真。

有一句话概括得很准：**一个永远无法失败的检查，只会给报告增加一行绿色。**

**面试怎么用**：被问「你的覆盖率怎么算」，这里是答案；被问「为什么不能更简单」，
这里也是答案。

---

## 7. 范围匹配：特异性优先级，不依赖文件顺序

`src/claimcheck/matcher.py:21-86`　`specificity()` / `scope_matches()` / `collect_known_cities()`

**做什么**：三种写法（枚举城市 / 全省 / 兜底），优先级 3 > 2 > 1。

**为什么不用「文件里靠后的生效」**：那样结果的正确性取决于 YAML 的书写顺序，
改一次排版就可能改变判定，而改动本身看起来无关紧要。这是隐式依赖。

**兜底怎么实现**：先收集本省所有被显式列举的城市，申请城市不在其中且存在
`fallback: true` 的规则，才匹配它。「其他地区」不是城市名，是「剩下的所有」。

**面试怎么用**：这是「规则怎么落地」最容易被追问细节的地方。

## 8. 冲突检测两级：一级高精度，二级启发式

`src/claimcheck/diagnose.py:310-414`　函数 `find_conflicts()`

**做什么**：

- **一级**：同 `kind` + 同 `check.field`，构造见证后结论不同 → 确定冲突
- **二级**：同一费用类别下，一条禁止一条放行 → 候选，需人工
- **声明验证**：规则里 `conflict_with` 声明的每一对，必须能构造出分歧见证，否则报「声明过时」

**为什么分两级**：一刀切会大量误报。限额规则说通过、无发票规则说不通过——
完全正常，它们查的是金额和凭证两件事。

**二级刻意排除两类**：联动规则（声明了 `affects`，天然与多条规则共存）、
整单级准入检查（彼此独立，不构成同一笔费用能否报销的分歧）。不排除会有 4 条误报。

**关键验证方式**：把规则复制到临时目录、**删掉所有 `conflict_with` 再跑**。
还能发现，才说明检测靠的是判断，不是复述人工标注。

**面试怎么用**：被问「你怎么证明这个功能真的有用」，这个验证方式就是答案。

---

## 9. 缺口检测：在有界枚举域上找没人管的格子

`src/claimcheck/diagnose.py:199-238`　函数 `find_gaps()`

**做什么**：枚举 (省, 市, 级别) 的住宿判断格子，找出没有任何规则覆盖的。

**枚举域从哪来**：`src/claimcheck/universe.py` 从 `data/lodging-subset.csv` 读，
再加上一个合成城市「未列出的市」去探兜底是否到位。**不凭空造域**，6 省 31 格 3 级别 = 93 组合。

**边界**：字段一多就组合爆炸。工业界用 OBDD 或超矩形空间求差，本实现只在小规则库上成立。
这条边界写进报告，不藏。

**面试怎么用**：被问「你的方法有什么局限」，这是主动亮牌的地方。

## 10. 问答：三类问题三条路

`src/claimcheck/qa.py:80-101`（`ask`）、`105-232`（`_compute`）、`236-289`（`_retrieve`）

**做什么**：先分类，再分流。

- **可计算**：读规则数据，答案里的数字不是生成的，带 `rule_id` 和明细表行
- **需读条文**：检索 + 逐字引用
- **拒答**：制度没覆盖

**为什么分类用规则不用模型**：分类结果决定答案来源，这个决定必须可复现。
模型分类改一次提示词就变，而且分错了从结果上看不出来。

**分类失败时退回检索，不是拒答**——宁可多检索一次，不把能答的挡掉。

**面试怎么用**：被问「为什么不全部走 RAG」，这是核心答案：
能算的问题不该交给可能出错的生成过程。

## 11. 引用校验：三层确定性检查

`src/claimcheck/verify.py`　`verify()`

**做什么**：

1. **引用存在**——条款能在语料里找到，且引文开头与原文逐字对齐
2. **数字可溯**——答案里每个数字都出现在被引片段中
3. **断言有据**——答案里的「不得 / 不予 / 禁止」被引片段里必须有

**为什么只查否定性断言**：「不超过」「按…计算」这类说法，原文往往用别的措辞
（「在限额内」「按规定标准」）。全查会大量误报，**而误报多了校验就会被忽略，比不校验更糟**。

**已知失效**：抽取式生成器不会编造，所以三项检查结构上不可能失败，捕获率为 0。
这一条如实写在评测报告里，不掩饰。

**面试怎么用**：被问「你怎么保证 AI 不说谎」，答案+诚实的局限一起给。

## 12. 评测：Wilson 区间与阶梯消融

`src/claimcheck/evaluate.py:28-40`（`wilson`）、`src/claimcheck/ablation.py:26-105`

**做什么**：

- **Wilson 区间**：50 条样本的比例估计必须带区间。不用正态近似——样本小、
  比例接近 0 或 1 时会给出越界结果。
- **阶梯消融**：L0 基线 → L1 加同义词 → L2 加版本过滤 → L3 加分类。每级只改一个开关
  （有测试检查这一点），否则说不清是谁的贡献。

**最有价值的两个数**：L3 带来 40%→72%；L1 零提升。

**面试怎么用**：被问「你怎么知道改进有效」，消融是标准答案；
被问「有没有无效的工作」，零提升那一项就是。
