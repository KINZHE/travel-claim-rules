# 制度问答的设计与边界

问答层的入口是 `python -m claimcheck ask "..."`。这份文档说明它怎么判断、依据什么、
以及哪些事它做不到。

## 一、先承认一件事：这个规模不需要 RAG

531 号全文 3606 字，加 2006 版、497 号、104 号，整个语料不到一万字。**可以整段塞进任何模型的上下文。**

所以「上检索」在这个规模不是必需，是选择。理由有两条：

1. 演示一条在真实规模下能用的路径——真到几十万字的法规库，整段直塞不可行
2. 为了让第 5 周能测出**检索到底比全文直塞好还是差**。不实现两种，就没有可比对象

两种上下文方式都实现了：

```bash
python -m claimcheck ask "..." --context retrieve   # 默认，检索 top-k 片段
python -m claimcheck ask "..." --context full       # 该版本全部条文
```

## 二、三类问题，三种处理

通用 RAG 项目的问题是：什么题都用「检索 + 生成」糊过去。本项目已有的规则引擎让问题可以分三类：

| 类型 | 例子 | 答案来源 | 可核查性 |
| --- | --- | --- | --- |
| **可计算** | 「南京出差，司局级，住宿最多报多少？」 | 读规则数据 | 100%：带 rule_id + 明细表行 |
| **需读条文** | 「报销需要哪些凭证？」 | 检索 + 逐字引用 | 高：引文与原文对齐 |
| **制度未覆盖** | 「出差期间生病的医疗费怎么报？」 | 拒答 | — |

第一类是区分点：**答出来的数字不是模型生成的，是从已验证的规则里读出来的，并且能指回条款和明细表行。**

### 分类用规则，不用模型

`classify.py` 用模式匹配 + 槽位抽取：

- 金额特征词（多少 / 上限 / 限额 / 标准 / 怎么算…）
- 费用类别词（住宿 / 伙食 / 市内交通 / 城市间交通）
- 地区（从 `data/lodging-subset.csv` 反查，城市名映射到省份）
- 人员级别（部级 / 司局级 / 其他人员）
- 时间（年份 → 版本基准日；月份 → 旺季判定）

为什么不用模型分类：分类结果直接决定答案来源，模型分类不可复现、改提示词就变。
规则匹配覆盖有限，但每次结果一样、可测、可解释。

**分类失败的默认行为是走检索，不是拒答。** 宁可多检索一次，也不要把能答的问题挡掉。

## 三、检索

### 字符二元组 + BM25

中文没有空格，但不想引分词库。用字符二元组：

> 「公杂费」→ 公杂、杂费

小语料上这是常见做法，好处是**可解释**——每个命中结果都能给出命中了哪几个二元组
（`Hit.matched`），而不是一个黑箱分数。

### 同义词映射

口语 → 制度用语，在切二元组之前做：

| 问句里 | 制度里 |
| --- | --- |
| 住酒店、酒店 | 住宿 |
| 打车的钱、出租车 | 市内交通 |
| 吃饭、餐费 | 伙食 |
| 上限、最多、能报多少 | 限额 |

这一步比换检索引擎便宜得多。调研里有项目发现它是最大的单点增益。

### 版本过滤在检索阶段就做

`search(query, as_of=...)` 只返回在该日期生效的条文。

**不能留到生成阶段再过滤**——模型看到旧条文就会照着答。调研中有项目统计，
约 50% 的错答源于新旧版本混用。

现行版本问答会排除 2006 版；问 2013 年的事，则只会命中 2006 版。

## 四、生成器

### 本期只实现抽取式

`ExtractiveGenerator` 挑最相关的一段条文，**原样引用，不改写**。

不改写是刻意的：改写就可能说出原文没有的话，而校验层正是靠「逐字可查」来判断的。

### LLM 版只留接口

`LLMGenerator` 抛 `NotImplementedError`。原因很简单：**没有 API key 就测不了，
测不了就无法证明它工作。** 在仓库里塞一批没跑过的代码，等于放了个装饰品。

接口约定与提示词模板写在 `generate.py` 的类文档字符串里，接上时要满足同样的约束：
只能用提供的条文作答、每个事实要能指到引用、不足时明确说不足。

**接上之后第一件事不是调提示词，而是把抽取式作为对照组跑同一套评测集**——
否则无法判断模型到底带来了什么。

## 五、引用校验

三层，全部确定性，不需要模型：

| 检查 | 判据 | 不通过意味着 |
| --- | --- | --- |
| 引用存在 | 引用的条款能在语料里找到；引文开头与原文一致 | 引用是编的，或把转述冒充成原文 |
| 数字可溯 | 答案里每个数字都出现在被引片段中 | 数字是编的或算错的 |
| 断言有据 | 答案里的「不得 / 不予 / 禁止」被引片段里必须有 | 宣称制度禁止了某事，而制度没这么说 |

### 只查否定性断言，不查所有判定词

「不超过」「按…计算」这类说法，条文原文往往用别的措辞（「在限额内」「按规定标准」）。
全查会大量误报，**误报多了校验就会被忽略，比不校验更糟**。

所以只查最要命的一类：宣称制度禁止某事。其余作为警告展示，不影响通过与否。

### 引用分三种

| kind | 含义 | 校验方式 |
| --- | --- | --- |
| `clause` | 条文 | 必须与语料逐字对齐 |
| `table` | 明细表行 | 检查内容非空；数值可溯源 |
| `secondary` | 二手来源 | 必须标明层级；给出可信度警告 |

`secondary` 是为伙食补助费准备的：那两个数（100 / 120 元）来自地方政府与高校转载，
不是财政部原件。答案里必须写出来源层级，不能含糊。

## 六、拒答分三种

混在一起就无法改进：

| 代码 | 含义 | 下一步 |
| --- | --- | --- |
| `NO_RETRIEVAL` | 没召回到相关条文 | 查检索或补同义词 |
| `INSUFFICIENT` | 召回到了，但不足以回答 | 补条文或明确转人工 |
| `NOT_COVERED` | 制度确实没规定 | 明确说没有，不猜 |

## 七、做不到的事

- **没有通用的「制度未覆盖」判断。** 现在只靠一张关键词清单识别超范围话题，
  清单之外的问题会去引用不相干的条文来回答。评测里有 6 道拒答题错了 5 道，就是这个原因。
  试过两条确定性判据——检索分数阈值、问句词汇在语料中的覆盖率——**两条都不可分**
  （拒答题与正常题的取值区间完全重叠）。要真正解决需要语义层面的判断，
  本期不用扩充关键词的方式去贴合测试题，那属于对评测集过拟合。
- **没有 LLM 生成。** 抽取式答案读起来生硬，它保证的是可核查，不是好读。
- **检索质量有限。** 纯字符二元组 + 少量同义词，不是语义检索。问句与条文用词差异大时会漏召回——
  例如「市内交通费标准是多少」在 2026 年的检索里，第一命中是 104 号而非 531 号第二十条
  （后者写的是「每人每天 80 元包干」，没有「标准」二字）。这类问题应当走可计算路径，
  事实上有金额特征词时会走；没有时会落到检索，结果不理想。
- **只覆盖 6 个地区。** 与规则库一致，见 `docs/known-gaps.yaml` G-001。
- **旺季判定依赖问句里的月份。** 问句没写月份时，答案给常规限额并附注旺季标准，
  不做「现在是几月」的推断。
- **分类覆盖率有限。** 只认「地区 + 级别 + 费用类别 + 金额特征词」的组合，
  换个问法可能落到检索。这是可接受的降级，不是错误。
