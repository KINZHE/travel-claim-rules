# 第 5 周评测方法：题目从哪来、指标怎么算、结论能推多远

## 一、这个评测最大的问题：自己出题自己考

题目由项目作者构造，评测也由作者运行。这个结构天然有循环论证的风险：
如果题目照着系统输出的措辞写，分数会虚高，**而且从结果上完全看不出来**。

三条约束，都不能完全消除这个风险，但能把风险压到可以说明的程度：

| 约束 | 做法 | 能防住什么 |
| --- | --- | --- |
| 从条文反向构题 | 先定依据哪几条条文，再写问题与标准答案；每条带 `basis` 字段 | 防「照着系统输出编标准答案」 |
| 约一半口语化 | 50 条里 24 条是口语问法（48%） | 防「照系统措辞出题」抬高模式匹配准确率 |
| 冻结 + 首次运行即结果 | 写完题后先跑一次记录分数，哈希写入 `FROZEN.md` | 防「看到哪题错了改哪题」 |

第三条最容易被绕过，所以它靠两个东西保障：哈希记录（能查出题目是否被改）和
一条写在报告里的声明（本次分数来自首次运行）。**声明没法用工具证明，但哈希可以核对。**

## 二、题目结构

```yaml
- id: Q-001
  question: 下个月去南京出差，我是司局级，住宿一天最多能报多少？
  style: colloquial              # formal / colloquial
  as_of: "2026-10-19"            # 按哪一天的制度判断
  expected:
    route: compute               # compute / retrieve / refuse
    citations_any:               # 至少命中一条即算引用正确
      - {doc_no: "财行〔2016〕71号", article_contains: 江苏省}
    facts: ["490"]               # 答案正文必须出现的字面内容
    must_not_contain: ["1100"]   # 不能出现的（抓「档位答错」）
  basis: 71 号明细表江苏省第 1 行，司局级 490
```

**`must_not_contain` 不是多余的。** 只检查 `facts` 抓不到一类错：
答案里出现 490，同时把 900 说成司局级的标准——两个都在，但有一个是错的。

## 三、指标定义

| 指标 | 判定方式 |
| --- | --- |
| 路径准确率 | 实际走的路（compute / retrieve / refuse）与预期一致 |
| 答案正确率 | 期望事实全部出现，且没有出现禁止内容；拒答题以「是否拒答」计 |
| 引用召回率 | 至少命中一条预期引用 |
| 拒答正确率 | 该拒的拒了、不该拒的没拒 |
| 校验通过率 | `verify.py` 三层检查全部通过 |
| 版本正确率 | 2014 年前的问题引用 2006 版、之后的不能只引 2006 版 |

### 为什么没有「citation precision」

计划里写的是 precision ≥ 0.95，实际改为 **citation validity**（即校验通过率）。
理由：抽取式生成器每次只给一到两条引用，precision 的分母恒为 1–2，算出来永远是 1.0，
不提供任何信息。validity 才有区分度——它抓的是「引用编造」或「转述冒充原文」。

这是一个**指标定义的修正**，不是降低标准。写在这里是因为报告里用了一个计划外的名字。

### 置信区间

50 条样本的比例估计，点估计的误差不能忽略。所有指标都用 **Wilson 区间**：

- 不用正态近似 `p̂ ± z√(p̂(1-p̂)/n)`：样本小、比例接近 0 或 1 时会给出越界区间（负数上界）
- Wilson 区间不会越界，且在极端比例下更合理

报告里两条指标的区间重叠时，应当认为**没有显著差异**，而不是比较点估计的小数位。

### 为什么不报总分

可计算题与拒答题性质完全不同。可计算 100%、拒答 30%，总体 75%——
这个总分掩盖了「拒答能力差」。所以按类型分别报，不合并。

## 四、阶梯消融

逐级加部件，每级跑同一套 50 题，**每级只改一个开关**（有测试检查这一点）。

| 级别 | 加了什么 | 想验证什么 |
| --- | --- | --- |
| L0 | 基线：全部走检索、无同义词、不过滤版本 | 对照组 |
| L1 | 同义词映射 | 口语题的召回提升 |
| L2 | 版本过滤 | 版本陷阱题不再混用新旧条文 |
| L3 | 三类问题分类（能算的走规则引擎） | **核心主张**：数值题准确率显著上升 |
| L4 | 引用校验 | 不提高正确率，提高**可知性** |

L4 单独看两个数：**捕获率**（答错的题里多少被校验标出）和
**误标率**（答对的题里多少被误标）。捕获率高、误标率低，校验才有用。

## 五、边界

- **样本量小**：50 条，区间宽度约 ±10 个百分点。不足以支持「超过 90%」这类强结论。
- **单一制度域**：只有差旅费一份制度、6 个地区子集。结论不能直接外推到其他业务。
- **抽取式生成**：没有 LLM，所以测的是「检索 + 抽取」而不是「检索 + 生成」。
  长上下文是否有用、生成式模型是否更好，本期**未验证**。
- **校验的捕获率为 0 是结构性的**：抽取式不会编造，所以校验抓不到错。
  它的价值要在接入生成式模型后才能体现。
- **失败清单是真实失效点**，不是待办列表。改不改取决于第 6 周的时间。

## 六、复现

```bash
# 跑评测并生成报告
PYTHONPATH=src python -m claimcheck eval --out docs/eval-report.md

# 只看阶梯消融
PYTHONPATH=src python -m claimcheck eval --ablation

# 核对题目集是否被改动
python scripts/freeze_eval.py
```

评测结果**完全确定**：同一份题目、同一份规则、同一套开关，跑两遍数字完全一致（有测试覆盖）。
